# 单商家购物小程序 实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 subagent-driven-development（推荐）或 executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法来跟踪进度。

**目标：** 交付一套单商家自用的购物小程序：商家按 SKU 给客户设专属价、客户看自己的价格下单、商家线下收款后在程序里批量确认收款，并能看到日/周/月营收与客户欠款。

**架构：** FastAPI 模块化单体（auth / customer / catalog / pricing / cart / order / report 七个模块，模块间只走 service 接口），单个 MySQL 库（15 张表）；微信原生小程序分「客户侧」「商家侧」两个分包，按角色分流。不接支付、不用 Redis、不用对象存储。

**技术栈：** Python 3.12、FastAPI、Pydantic v2、SQLAlchemy 2.0、Alembic、MySQL 9、PyMySQL、python-jose、pytest、httpx；小程序为微信原生 + TypeScript。

**规格：** [docs/superpowers/specs/2026-10-17-architecture-design.md](../specs/2026-10-17-architecture-design.md)

## 全局约束

- Python 3.12；后端依赖写在 `backend/pyproject.toml`，不引入 Redis、对象存储、ReportLab/openpyxl
- 数据库 MySQL 9，InnoDB，字符集 `utf8mb4`，排序规则 `utf8mb4_0900_ai_ci`
- 主键统一 `id BIGINT UNSIGNED AUTO_INCREMENT`；每张表默认含 `created_at`、`updated_at`，`audit_log` 只有 `created_at`
- 金额一律 `DECIMAL(12,2)`，Python 侧用 `decimal.Decimal`，禁止 float
- 时间一律存 Asia/Shanghai 本地时间的 `DATETIME`
- 表名用单数，订单表名为 `orders`
- 价格只能由 `pricing` 模块解析；其他模块禁止读 `customer_price` 或 `sku.default_price`
- 模块之间只走 service 接口，禁止跨模块 import 对方的 `models` / `repository`
- 客户数据隔离在后端强制：客户只能访问属于自己的订单与购物车
- `audit_log` 动作只有四个：`price.change`、`order.cancel`、`order.confirm_receipt`、`order.undo_receipt`
- JWT 有效期 120 分钟，无 refresh token；401 时小程序重新 `wx.login()`
- 接口前缀 `/api/v1`；客户资源在 `/me/*`，商家资源在 `/admin/*`
- API 测试跑在独立测试库 `shoper_test` 上

## 审查重点（Review Focus）

1. **专属价被设成 0 或负数**：商家误把专属价填成 `0` 时，不能当成「免费」也不能当成「恢复默认」，必须返回 `400 INVALID_ARGUMENT` —— 任务 7 覆盖
2. **购买已下架或已停用的 SKU**：客户把商品加进购物车后商家下架了它，下单必须失败并明确指出是哪个 SKU，不能静默成交 —— 任务 9 覆盖
3. **批量确认收款传入重复订单号或一次 500 个订单**：必须去重、在一个事务内完成、不能把同一张订单统计两次 —— 任务 10 覆盖
4. **客户取消订单与商家确认收款并发**：不能出现「已取消」和「已收款」同时成立的状态 —— 任务 10 覆盖
5. **订单跨月**：下单在上月、确认收款在本月，营收只能计入本月 —— 任务 11 覆盖

## 文件结构

### 后端

| 文件 | 职责 |
| --- | --- |
| `backend/app/main.py` | 创建 FastAPI 应用、挂路由、挂异常处理、挂静态目录 |
