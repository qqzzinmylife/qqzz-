# 单商家购物微信小程序

给私人做的一个项目，帮助商家管理商品。

一个由 Python 后端提供接口、微信小程序提供客户与商家操作界面的购物系统。

项目面向单个商家自用，核心能力是商品购买、客户差异化定价、订单管理、票据生成和营收统计。小程序只包含购物相关功能，不包含点赞、评论等社区功能。

## 项目目标

- 客户可以在微信小程序中浏览商品、查看自己的价格、下单和查询订单。
- 商家可以为不同客户设置不同商品价格。
- 客户没有专属价格时，系统自动使用商品默认价格。
- 商家可以随时调整指定客户的价格，且不影响历史订单。
- 系统可以根据订单和收款记录生成票据或对账单，方便商家统计。
- 商家可以通过小程序查看当日营收、客户消费情况和待收款情况。

## 已确认需求

- 只做一个商家自己使用的系统，不开发多商家平台。
- 小程序支持客户和商家两种角色，商家通过角色权限进入管理页面。
- 商品价格按 SKU 管理，SKU 表示商品的具体规格。
- 商品具有默认价格。
- 商家可以为指定客户设置专属价格。
- 客户下单时优先使用客户专属价，没有专属价时使用商品默认价。
- 商家可以随时更换客户并设置不同价格。
- 订单生成时必须保存价格快照。
- 历史订单、票据和统计不受后续价格调整影响。
- 商家可以在小程序端查看当日营收和不同客户的消费情况。

## 角色

### 客户

- 微信登录并绑定客户档案。
- 浏览商品和商品规格。
- 查看当前客户最终生效的价格。
- 加入购物车、提交订单。
- 查看订单、订单小票和客户对账单。
- 查看已支付、待支付或欠款信息。

### 商家

- 管理客户档案。
- 选择客户并设置客户专属价格。
- 恢复客户的商品价格为默认价格。
- 查看和管理订单。
- 记录线上或线下收款。
- 查看当日营收、订单数量和客户消费统计。
- 生成订单小票和客户对账单。

## 核心定价规则

价格解析优先级如下：

```text
客户专属价 > 商品默认价
```

后端根据当前客户和 SKU 解析最终价格：

```text
如果存在该客户与 SKU 的当前有效专属价：
    使用客户专属价
否则：
    使用该 SKU 的默认价格
```

商品必须绑定到一个 SKU。商品只有一个规格时，也创建一个默认 SKU，以便统一处理价格、订单和统计。

### 价格变更规则

- 商家修改价格后，只影响之后创建的订单。
- 已创建订单、订单小票、对账单和营收统计继续使用下单时的价格。
- 客户购物车中的价格仅用于展示，提交订单时由后端重新计算。
- 如果客户确认订单后、提交订单前价格发生变化，后端应返回最新价格并要求客户重新确认。
- 取消客户专属价后，该客户之后看到商品默认价。
- 价格变更需要记录操作人、修改前后价格和修改时间。

示例：

```text
商品 A 默认价：100 元
张三专属价：80 元
李四未设置专属价：显示 100 元

张三下单后，订单保存单价 80 元。
商家后来把张三专属价改为 90 元，张三之后看到 90 元。
张三之前的订单仍然按照 80 元统计。
商家取消张三的专属价后，张三之后看到 100 元。
```

## 主要业务流程

```text
商家创建客户档案
-> 客户微信登录并申请绑定
-> 商家确认绑定
-> 商家为客户设置专属价格
-> 客户浏览商品
-> 后端解析客户价格
-> 客户加入购物车
-> 客户提交订单
-> 后端重新定价并保存价格快照
-> 生成订单和订单小票
-> 线上支付、线下收款或记入月结
-> 商家发货或交付
-> 生成客户对账单和营收统计
```

### 数据看板

- 今日订单金额。
- 今日实收金额。
- 今日退款金额。
- 今日净营收。
- 今日订单数量。
- 待收款金额。
- 新增客户数量。
- 客户累计消费。
- 客户订单次数。
- 客户最近下单时间。
- 客户消费排行。

统计时必须区分：

- 订单金额：客户下单后形成的订单总额。
- 实收金额：实际收到的金额。
- 退款金额：已经退回的金额。
- 净营收：实收金额减去退款金额。
- 应收账款：已经下单但尚未支付的金额。

### 推荐技术栈

- 小程序端：微信原生小程序 + TypeScript。
- 后端：Python 3.12 + FastAPI + Pydantic + SQLAlchemy。
- 数据库迁移：Alembic。
- 数据库：MySQL 8，开发阶段可以使用 SQLite。
- 缓存和锁：Redis。
- 文件存储：腾讯云 COS 或阿里云 OSS。
- 支付：微信支付 API v3。
- 票据：ReportLab 或 WeasyPrint 生成 PDF，openpyxl 导出 Excel。
- 部署：Docker + Nginx + Uvicorn/Gunicorn。
- 管理界面：第一版放在微信小程序中；后续再评估 Web 管理后台。

## 商家价格管理方式

商家可以从客户进入价格管理：

```text
客户列表 -> 选择客户 -> 客户价格管理 -> 搜索商品
-> 设置专属价或恢复默认价
```

也可以从商品进入价格管理：

```text
商品列表 -> 选择商品/SKU -> 客户价格列表
-> 选择客户 -> 设置专属价或恢复默认价
```

建议商品价格列表至少展示：

```text
商品规格 | 默认价 | 该客户价格 | 状态 | 操作
```

第一版可以只支持逐个设置价格。客户和商品数量增加后，再增加：

- 复制某个客户的价格表到另一个客户。
- Excel 批量导入客户价格。
- 按客户分组统一设置价格。
- 价格生效时间和失效时间。

## 票据与对账

这里的票据默认指交易小票和客户对账单，不等同于税务发票。

- 订单小票：一个订单一张，记录客户、商品、规格、单价、数量、总额、支付状态和生成时间。
- 客户对账单：按客户和时间段汇总多张订单，展示应收、已收和欠款。
- 税务发票：如果业务需要，需要另外接入电子发票平台。

票据应使用订单价格快照生成，不能重新读取当前客户价格或当前商品默认价格。

## 权限和安全

- 客户只能查看自己的订单、价格、小票和对账单。
- 商家只能修改自己经营范围内的客户、商品、价格和订单。
- 价格必须由后端计算，不能信任小程序提交的价格。
- 订单创建需要幂等处理，避免重复下单和重复收款。
- 支付回调需要验签、幂等和异常重试处理。
- 重要操作需要保留审计日志，包括价格修改、订单改价、收款和退款。
- 客户的专属价格绑定 `customer_id`，不要直接绑定微信 `openid`。
- 客户绑定、手机号、地址和支付信息需要遵守微信平台和隐私保护要求。
